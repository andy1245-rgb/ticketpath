# 28 — The publish script's duplicate mint: resume file, retries, and what the rehearsal found

**Run:** DEVNET-RESUME, 2026-11-07. **Result: `tools/devnet_publish.py` no longer needs a
second mint when a run dies.** Everything below was measured in this run, on this machine,
against local ledgers; nothing was sent to devnet, no faucet or airdrop was called, and no
keypair file was read by hand.

## 1. The failure being fixed

A devnet run deployed the program and minted a mint, then died reading a signature status:

```
FAILED: getSignatureStatuses: https://api.devnet.solana.com did not answer (HTTPError)
```

The rerun minted a **second** mint, because the first mint's address had only ever existed in
a dead process's memory: the artefact that records it is written at the very end of the run.
The rerun's at-cap transfer landed, its status read failed again, the over-cap refusal was
never exercised, and `records/devnet-artefacts.json` was never written.

Two independent causes, and both are now closed:

| # | Cause | Fix |
|---|---|---|
| 1 | one HTTP failure ended the run, and no retry existed | `rpc()` retries transport failures (5xx/408/429, timeouts, resets, truncated bodies, and the jsonrpc messages that mean "ask again") four times with 0.5s/1s/2s backoff, prints each retry, and then reports one sentence naming the attempt count and the last error |
| 2 | the mint's address was invented by `spl-token create-token` inside the call that created it | the mint keypair is generated by this script and its address is written to the resume file **before** the transaction that creates it |

## 2. What the resume file holds

`records/devnet-progress.json` (and `.local.json` for a rehearsal), git-ignored, `0600`,
written with `os.replace` so a crash leaves the old file or the new one and never half of
one. Fields are public identifiers and integers only:

`mint`, `mintMetadata`, `buyer`, `authorityAta`, `buyerAta`, `record`, `extraMetas`,
`ticketsMinted`, `memo{signature,slot,quoteHash}`, `transfers{acceptedAtCap,refusedOverCap}`,
`pending{leg:{signature,blockhash}}`, `balancesBefore`, `balancesAfter`, `programId`,
`cluster`, `version`, `checkerVersion`, `completedAt`.

`Progress.save` refuses to write a path (anything starting `/` or `~`), a key handle (any
value containing `keypair`), a list, or a field not in that tuple. The file is a run's
bookkeeping and not evidence, so the artefact stays the published record; but a rule that
only held for the published file would not be a rule.

A transaction's signature is written the instant `sendTransaction` returns it, together with
the blockhash it was signed against. A rerun that finds one asks the cluster whether it
landed rather than sending it again. A transfer moves a ticket, so "not visible" is not
treated as "did not happen": the run waits until the blockhash is provably dead
(`isBlockhashValid` returns false) before it will resend, and otherwise stops and says to run
it again. Three states are distinguished per leg: **recorded** (re-read, never resent),
**pending** (ask, then decide), **nothing** (send).

## 3. Four races the local rehearsal found that devnet never shows

A `solana-test-validator` resumed on a kept ledger answers `getHealth` before it has replayed
its accounts, so for a few seconds every account reads as absent. Measured on this machine:
health `ok` at +0.5s, the program account visible at +4.5s, the mint at +5.0s, and one run
that saw neither for nine seconds.

| What the stale "absent" did | Consequence if unfixed | Fix |
|---|---|---|
| the resumed run re-ran `create-token` for a mint that existed | `Account ... already in use`, run dies | patient lookup (`wait_for_account`, 20 x 0.75s) for every candidate that predates the process, and a create that fails because the account exists is treated as done |
| `spl-token balance` failed and the code read 0 | **a third ticket minted**, and the pair's arithmetic then fails forever | a failed read is an error, never a zero; retried while the CLI says "not found" |
| `spl-token initialize-metadata` answered `AccountNotFound` | run dies after the mint exists | one retry after the account becomes visible |
| `spl-token mint` answered `Account ... not found` | run dies on a resume that should have worked | `settled()`: a CLI "not found" is retried (the CLI lags this process's RPC by about a second, measured), anything else is raised at once |

## 4. The rehearsal, with injected failures

`--inject after:<step>` and `--inject rpc:<method>:<count>` exist for this and are armed by
an explicit flag only — nothing reads the environment. Five runs, fresh ledger each time
except where a resume is the point:

| # | Run | Result |
|---|---|---|
| T1 | fresh ledger, no fault | **pass**, artefact written, seller 1 / buyer 1 from (2, 0), over-cap refused with `6010` |
| T2a | `--inject after:mint.created` | **stops on purpose**, resume file holds the mint and nothing else |
| T2b | rerun on the same ledger | **pass**, log reads `mint: reusing ... from the resume file`; count of Token-2022 mints of that size on the ledger after both runs: **1** |
| T3a | `--inject after:transfer.acceptedAtCap.sent` | **stops on purpose**, `pending.acceptedAtCap` holds the signature and blockhash |
| T3b | rerun | **pass**, `had already landed; recording it instead of resending`, and the artefact's at-cap signature is the same transaction T3a sent |
| T4 | `--inject rpc:getSignatureStatuses:2` | **pass**, two `HTTPError 502; retrying` lines, then a complete artefact |
| T5 | a rerun after a finished run, with `--restart` | **pass**, both legs reused from the artefact, nothing resent |

`--restart` forgets the resume file only. It cannot be allowed to turn a finished run into one
that resends its transfers, so the mint, memo and both legs are taken from the artefact of the
same cluster first.

## 5. What is still untested

- **A real devnet run.** Everything above is a local ledger. The retry paths are exercised
  against injected 502s, not against devnet's actual failure modes.
- **A run killed by SIGKILL**, or by the machine, in the middle of `sendTransaction`. The
  resume file's last write survives (`os.replace`), but the pending-signature path has only
  been tested with a fault raised immediately after the send, not with the process vanishing
  between the send and the write.
- **`isBlockhashValid` against devnet.** Local returns `{"value": bool}`. If the devnet node
  does not answer it, `blockhash_is_dead` returns "not dead" and the run stops rather than
  resending — safe, but untested there.
- **The orphaned mints already on devnet** (`8XL9GDs9...`, `Gc8pqx5r...`). This change stops
  the next duplicate; it does not clean up the two that exist, and nothing should treat
  either as the project's mint.
- **The metadata shape** the on-chain check parses (`extensions[].extension ==
  "tokenMetadata"`) was read back from the local validator only.
