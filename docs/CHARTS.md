# Chart and animation assets from a `market_swarm` dataset

`docs/charts/` holds five SVG assets and one index page, generated by
`tools/swarm_charts.py` from a dataset the trading-swarm harness wrote. Everything in this
directory is **synthetic**: scripted agents on a simulated gateway, not observed prices.

That is not a disclaimer bolted on at the end. It is the first thing each file says, in its
own visible text and in its `<title>` element, and it is the thing the tool re-checks before
it says an asset is good.

```bash
python3 tools/swarm_charts.py generate --out docs/charts --dataset <path.jsonl> [...]
python3 tools/swarm_charts.py verify   --out docs/charts [--dataset <path.jsonl> ...]
```

Standard library only. No network, no chain, no third-party plotting, no binaries: each
asset is text and diffs in a review.

## What the assets are

| asset | what it shows | drawn from |
|---|---|---|
| `price-path-evt_capped.svg` | the price path of the capped event: executed custody moves joined in row order, refusals marked as refusals, listings and unmet asks hollow, the cap ceiling and the face value as reference lines | one capped dataset |
| `price-path-evt_monitored.svg` | the same for the monitored record, whose cap sits at the u16 field maximum: that ceiling is off the top of the scale, so it is named in the legend as off-chart instead of drawn | one monitored dataset |
| `markup-vs-time-to-event.svg` | resale markup over face value placed on the simulated horizon, one series per mode, with the median executed markup at each point on the horizon drawn as a mark labelled `n`; a dashed line joins two neighbouring points only when both have at least two executed resales | both datasets |
| `hops-and-holding.svg` | a. custody hops per ticket (1 = the primary buy), b. holding duration in rounds from the buy round to the resale round | both datasets |
| `ticket-hop.svg` | one ticket's custody chain and a refusal bouncing off the ceiling. Animated with CSS keyframes, no JavaScript; the static frame and the reduced-motion frame carry the whole story in words | the first dataset with a refusal |
| `index.html` | what each asset is, the dataset it came from, the digest, and the label | the manifest the other five carry |

Every asset carries, in its text and in its `<title>`: the word `SYNTHETIC`, the dataset
file name, the run id, and the one sentence saying what the picture is not.

## The dataset these were generated from

Produced on this machine by a dry run of the example config (the scripted policies, no
socket, no validator, no key):

```bash
python3 -m market_swarm run --config market_swarm/example-run.json --dry-run \
    --kill-after 120 --out .swarm-runs
```

| dataset file | run id | event | mode | rows | sha256 (first 16) |
|---|---|---|---|---|---|
| `sw20261108T054830Z6297-evt_capped-SYNTHETIC.jsonl` | `sw20261108T054830Z6297` | `evt_capped` | capped | 51 | `d8fbe6a50b4efbf2` |
| `sw20261108T054830Z6297-evt_monitored-SYNTHETIC.jsonl` | `sw20261108T054830Z6297` | `evt_monitored` | monitored | 55 | `92dba3b4261937f3` |

The datasets are **not in this repository**. `.swarm-runs/` is git-ignored, because the
repository is code only. Each asset records the dataset's file name and its full sha256, so
a reader can tell which file a picture came from and can check it if they have that file;
`verify --dataset <path>` re-hashes it, rebuilds the series from it, and fails if either the
file or the picture has changed.

**A dry run** means the gateway returned what the hook *would* have done: no transaction was
built, signed or sent, and every row carries `chain: "simulated"`. Dry runs are allowed here
because the scripted policies are the default path for a dataset, so most runs are dry; the
asset says `DRY RUN` in red in the header and again in the footer, and the provenance records
`dry_run: true`. A live run is charted identically, with that line absent. The prose about a
refusal branches on the same flag: a dry row says the hook *would* refuse it and that nothing
was built, signed or sent, because a refusal that never touched a chain is not a refusal that
happened (`records/findings/31`, H1).

## Regenerating all of it

From the repository root, on any machine with Python 3.12 and this tree:

```bash
# 1. a dataset. under a second, no network, no chain, no key.
python3 -m market_swarm run --config market_swarm/example-run.json --dry-run \
    --kill-after 120 --out .swarm-runs

# 2. the assets. take both files the run printed; two modes is what makes the comparison
#    chart a comparison rather than one series and a note.
python3 tools/swarm_charts.py generate --out docs/charts \
    --dataset .swarm-runs/<run>-evt_capped-SYNTHETIC.jsonl \
    --dataset .swarm-runs/<run>-evt_monitored-SYNTHETIC.jsonl

# 3. the check that the assets are what the tool would write.
python3 tools/swarm_charts.py verify --out docs/charts --dataset \
    .swarm-runs/<run>-evt_capped-SYNTHETIC.jsonl --dataset \
    .swarm-runs/<run>-evt_monitored-SYNTHETIC.jsonl
```

A fresh run writes a new run id and new digests, so the regenerated assets differ from the
committed ones in three places: the run id, the dataset digests (and the file name that
carries the run's timestamp), and `generated_at`, which is the one wall-clock field. Everything
else is a function of the data: two `generate` runs over the same datasets at different
seconds differ only in the timestamp, and at the same second they are byte-identical.

One dataset is a legitimate input. With a single `--dataset` the price path is drawn for
that event, and the comparison chart draws one series and says in the picture that there is
no second mode to compare against, rather than inventing one.

## The label rule

The rule the dataset writer already enforces, inherited and enforced again here:

1. Every asset carries the word `SYNTHETIC` in its visible text and inside its `<title>`.
2. Every asset carries the dataset file name and the run id, in both places.
3. Every asset carries one sentence: *not evidence about any real ticket market*. It is the
   whole sentence in the `<title>`, in the `<desc>`, and in the footer of the picture.
4. Every asset carries a provenance block (`<metadata id="provenance">`) with the dataset's
   sha256, the sha256 of the series it drew, and the facts the picture was drawn from.
5. Nothing that is not labelled gets drawn: the tool refuses a dataset the harness's own
   verifier rejects, and refuses a sidecar that is not labelled synthetic.

`verify` re-checks 1 to 4 by reading the files, not by trusting the code that wrote them. It
re-renders each asset from its own provenance and compares the bytes, which catches a hand
edit to the file. That on its own only proves the file agrees with the block it carries, so
when a dataset can be located (beside the assets, or passed with `--dataset`) `verify` also
re-loads it and rebuilds the series with the same function `generate` used, then compares
that series with the recorded one. Narrower checks run first so a failure names the
problem instead of saying "the bytes differ":

| what it checks | what a failure means |
|---|---|
| the word `SYNTHETIC` in the `<title>` and in the visible text | a saved image would carry no label |
| the not-evidence sentence in the `<title>` and in the visible text | the honest line was removed |
| the dataset file name and the run id in both | the picture lost its provenance |
| sha256 of the embedded series | the numbers were changed after the digest was taken |
| the series rebuilt from the dataset, against the recorded series | the picture is not of the data in the file it names |
| the dataset's sha256, when the file is present | the picture is of a different file now |
| each manifest entry against the asset's own provenance | the index carries a digest no asset has |
| re-render from the provenance, byte for byte | the file was edited by hand, anywhere |

The last row is the broadest and the only one that says "anywhere": it compares the whole
file with what the tool renders from the block inside it. It prints `PASS` with the counts,
or `FAIL` with every problem it found, not just the first.

**Exit codes.** `0` means every asset's series was rebuilt from its dataset and matched. `2`
means at least one check failed. `3`, printed as `PASS LABELS ONLY`, means the labels and the
internal consistency passed but at least one dataset could not be located, so nothing about
the numbers was checked against data. On a fresh clone with no `.swarm-runs/` that is what
`verify --out docs/charts` returns; pass `--dataset` to check the numbers.

## What the tool refuses, and why

- **`complete: false`** in the sidecar. A run that stopped early has a path that ends in the
  middle of its horizon, and a picture cannot say "this is half a run" honestly enough.
- **A dataset with no sidecar.** Without one there is nothing saying the run finished.
- **A dataset and a sidecar that disagree** about the run id, event id, dry-run flag or
  chain. The pair is one artefact, or it is not provenance.
- **A dataset whose rows span more than one event.** One asset draws one event.
- **A dataset that fails `market_swarm.datasets.verify_dataset`.** That is the same verifier
  the CLI's `verify-dataset` verb runs, so the schema is not re-implemented here.
- **A price that is not a non-negative integer** is not drawn and is counted in the picture
  instead: a dataset that slipped past the verifier does not take the chart down with it.

## What the charts do not say

Every number on them is class **E**: synthetic, generated, and not evidence about any real
market (`records/findings/31`, "Why it exists" and "What it is not"). In particular:

- A price path here is what scripted policies did against a simulated gateway. It is not a
  forecast, a history, or an estimate of any real resale price.
- A refusal is the program's own cap predicate refusing a staged price. In a dry run it is
the verdict the predicate *would* return: nothing was built, signed or sent. Either way it
shows the mechanism works; it says nothing about whether a cap is the right policy.
- The two modes differ in one field of the record. Nothing about the difference generalises
  to a real market, because there is no real market in this data at all.
- The hop counts and holding durations describe these agents, not buyers.
- A skipped buy is a limit price nobody met, so it is counted and left off the price path: a
  chart that mixed bids with asks would read as a price history that never happened.

`index.html` is self-contained: no external font, no stylesheet, no CDN, no script. It opens
from disk.
